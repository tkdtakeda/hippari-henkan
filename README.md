# hippari-henkan

引張試験ファイル（島津 TrapeziumX / TrapeziumX-V）の **変換 ＋ 解析ツール**。

`index.html` を**ダブルクリックで開くだけ**で動きます。サーバも外部ライブラリも不要で、
ファイルの読み込み・CSV 変換・作図・特性値の算出はすべてブラウザ内で完結します（通信は一切しません）。

```
index.html                 画面の骨組み（外部 CDN は参照しない）
assets/css/tokens.css      デザイントークン（色・余白・文字・高さ・モーション）
assets/css/app.css         レイアウトとコンポーネント
assets/css/report.css      レポートモード（用紙）・線図の最大化ウィンドウ・印刷
assets/js/util.js          小道具（整形・アイコン・DOM ヘルパ）
assets/js/binary.js        バイナリ操作と TLV 文字列トークン抽出（仕様 §4）
assets/js/parser.js        TrapeziumX / -V の解析（§3・§5）／1.py v5 の移植
assets/js/csv.js           CSV の出力と入力（§6・§11.1）
assets/js/zip.js           Zip（store 方式・内蔵実装）（§7.2）
assets/js/analysis.js      解析エンジン（§12〜§16）
assets/js/chart.js         線図（Canvas レンダラ／ズーム・パン・ミニマップ）
assets/js/report.js        レポートモード（用紙 1 枚の組み立て）
assets/js/app.js           状態・描画・イベント
```

JS は `type="module"` を使わない古典スクリプトです（`file://` では ES Module が CORS で
読めないため）。読み込み順は `index.html` の末尾を参照してください。

| そのほかのファイル | 役割 |
|---|---|
| `trapezium_html_converter_spec.md` | 実装仕様書（rev.2） |
| `基本設計.md` | UI の設計原則。画面を作る・直すときは毎回これに照らして確認する |
| `1.py` | 元の Python 版パーサ（v5）。データ変換ロジックの参照実装 |

## つかいかた

1. `index.html` をブラウザで開く（Chromium 系 / Firefox の最新版）。
2. 試験ファイルをドロップする、または「ファイルを追加」から選ぶ。複数同時可。
   - `.xtux` / `.vtav` … 変換（CSV 出力）＋ 解析
   - `.csv` … 解析のみ（Trapezium の CSV エクスポート等。文字コードは自動判別）
3. **確認は出しません。** 落とした時点で変換が始まり、終わると線図まで表示します。
   読み込んだデータは変換する以外に使い道が無いため、間に「変換しますか」を挟みません。
   - 右上のボタン: `変換中… 2 / 4 件` → `17 ファイルを ZIP でダウンロード`
   - 変換中に追加でドロップした分も、同じ変換の待ち行列に入ります。
   - 変換が終わると、いま入れたファイルを選んだ状態で「線図」タブを開きます。
4. 個別に保存したいときは、各ファイルのカードにある分割ダウンロードのチップを押します。

## 線図の操作（拡大・移動）

全体像だけでは何が問題か分からないので、線図は自由に拡大して見られます。

| 操作 | 動き |
|---|---|
| ホイール | 拡大・縮小（`Shift` で X のみ、`Alt` で Y のみ） |
| 左ドラッグ | 表示範囲の移動（パン） |
| 右ドラッグ | 範囲を矩形で囲って拡大 |
| ダブルクリック | 全体表示に戻す |
| ← → ↑ ↓ | 移動（`Shift` で 3 倍・線図をクリックしてから） |
| `+` `−` `0` | 拡大／縮小／全体表示 |

- **数値で範囲指定**: バーの `X 下限 〜 上限` / `Y 下限 〜 上限` に直接入力できます。
  空欄にしたところだけ自動範囲に戻ります。`‹ ›` `⌄ ⌃` は表示幅の 15% ずつスクロールします。
- **拡大して確認**: `全体` `直線域` `耐力点` `0.2%耐力` `破断点` のボタンで、その位置へ一発で
  拡大します。押せないボタンには理由（検出できていない旨）が出ます。
- **全体図（ミニマップ）**: 線図の下に常に全体を表示し、いま見ている範囲を枠で示します。
  枠はドラッグで移動でき、枠の外を押すとその位置へ飛びます。ホイールで拡大縮小もできます。
- **最大化**: 線図カード右上の `最大化` を押すと、画面いっぱいの別ウィンドウで開きます。
  拡大・全体図・注目点ジャンプ・PNG 保存はそのまま使えます。`Esc` か `もとの画面に戻す` で
  閉じると、**そのときの表示範囲のまま**もとの画面に戻ります。ほかの線図を閉じて場所を作る
  必要はありません。「時間-応力を並べる」で出した副図にも `最大化` があり、そちらは軸を
  時間-応力に固定して開きます。
- **解析タブの判定内訳**から「線図で確認」を押すと、その判定の根拠になった区間（直線域など）へ
  線図を切り替えて拡大します。
- X 軸・Y 軸は `ひずみ / 変位 / ストローク / ひずみ(ストローク基準) / 時間 / 応力 / 試験力 / 速度`
  から自由に選べます。
  「時間-応力を並べる」で 2 つの線図を同時に表示できます（それぞれ独立に拡大できます）。

## レポートモード

画面右上の `単票 / レポート / 一覧` から `レポート` を選ぶと、選択中のファイルについて
**A4 縦の用紙 1 枚**を組み立てます。上に表、最下部に 応力-伸びの全体像グラフ。
正式な書面として出すため、**用紙の中には説明文を入れません**（表・グラフ・見出しだけ）。

| 場所 | 内容 |
|---|---|
| タイトル | 自由に書き換えられます。既定は `ロットNo._引張試験結果`。`既定に戻す` でいつでも戻せます |
| 見出し | ロットNo.・試験方向・採取位置（あるときだけ）・試験日・試験片形状・厚さ×幅・ゲージ長・耐力点（速度法で算出）・入力ファイル |
| 表 | 列 = 試験力／引張強さ／伸び／弾性率／応力増加速度／ひずみ速度／実績クロス変位速度／厚さ／幅　行 = **名前・元データ名・単位・合格範囲・測定値・合否判定**。**出す列は選べます**（下記） |
| グラフ | 応力 － 伸び の全体像（横軸は伸び計基準のひずみ [%]。常に全範囲。拡大は「単票 › 線図」または線図の最大化で） |

グラフの横軸は元 Trapezium と同じ **`変位計1(ひずみ)(%)`＝伸び計基準のひずみ**に合わせています。
`×` は変換元ファイルの `破断点_変位(ひずみ)` の位置で、ひずみ [%] をそのまま置きます
（応力はその位置にいちばん近い測定点の値を使い、線の上に印が乗るようにします）。

### 表示項目（表に出す列を選ぶ）

`.xtux` では弾性率を出さない、といった運用があるため、**どの列を表に出すかを選べます**。
レポート上部のツールバー `表示項目` を押すとチェックボックスの一覧が出ます。

- 既定はすべて表示。並び順は選んだ順ではなく、**いつも同じ定義順**です。
- 選択はこの端末に保存され（`localStorage`）、次に開いたときも同じ列で出ます。
- `既定に戻す（すべて表示）` でいつでも全表示へ戻せます。チェックを全部外したときも全表示に戻ります。
- 列に出す値がファイルに無いときは、従来どおり「取得できず」と書きます。
  **列そのものを消すのは、この選択だけ**です。

各列の見出しは「名前」と「元データ名（`最大点_試験力` など変換元ファイルでのラベル）」の
**2 行に分けて**います。1 つのセルに 2 段を詰めると行数の違いで文字の高さが揃わず、
横に並べたときガタガタに見えるためです。名前は段の下端、元データ名は上端でそろえ、
段の境目が全列で一直線に通るようにしています。
狭い列でも**単語の途中では折り返しません**（改行できるのは `_` の直後と、あらかじめ決めた位置だけ）。

### ファイル名の読み解き

ファイル名は `年月日_連番_ロットNo._[採取位置]試験方向.拡張子` として読みます。
区切りの `_` はロット No. までの 3 個だけで、**必ず 4 フィールド**になります
（第 4 フィールドにハイフンや数字は入りますが `_` は入りません）。

| 位置 | 項目 | 例 |
|---|---|---|
| 1 | 年月日（YYYYMMDD） | `20260721` |
| 2 | 連番 | `1321` |
| 3 | ロット No. | `N4381E0` |
| 4 | 採取位置 ＋ 試験方向 | `BOT-L` |

第 4 フィールドは**末尾から試験方向を切り出し、残りを採取位置**とします。
試験方向は `LT` / `L` の 2 種類だけで、**必ず `LT` を先に**判定します。
残りの末尾にハイフンが付いていたらそれだけ落とし（`BOT-` → `BOT`）、内側のハイフンは残します。

| 第 4 フィールド | 採取位置 | 試験方向 |
|---|---|---|
| `LT` | （なし） | `LT` |
| `L` | （なし） | `L` |
| `BOT-L` | `BOT` | `L` |
| `1-10DL` | `1-10D` | `L` |

採取位置の記号は `U D S 2 E C OS DS` のほか `BOT` や `1-10D` のような番号付きも入るため、
リストで絞らず「試験方向を除いた残り全部」を採取位置として扱います。
採取位置が空のときは、用紙の見出しにその項目自体を出しません。

ロット No.・試験方向・採取位置はここから取り、タイトルの既定にもこのロット No. を使います。
読み解いた結果はレポート上部に並ぶので、取り違えていればその場で分かります。
`_` の数が合わない／第 4 フィールドが `L` `LT` で終わらないときは、その旨を警告として出し、
読めた分はそのまま表示します（値を勝手に捨てません）。

用紙は印刷と同じ A4 縦の寸法で置きます。`全体表示`（既定）は画面に入る倍率まで縮めて 1 枚全部を、
`原寸` は 100% で表示します（倍率はバーの「表示 ○○ %」に出ます）。
`印刷 / PDF 保存` は用紙だけを **A4 縦 1 ページ**で刷ります（画面の枠・ツールバーは印刷されません）。

### 測定値・合格範囲・合否判定

**測定値も合格範囲も、変換元ファイルから出てくる値をそのまま出します。**
このツールの解析値はレポートには入れません（解析値と見比べるときは 単票 › 解析 タブ。
伸びだけは解析タブのカードもファイル記録値に揃えてあり、計算値は「破断点の決定」に並べます）。
合格範囲もファイルから読むので、**判定は装置の値どうしの突き合わせ**になります。
ファイルに値が無い項目は「取得できず」（寸法は「未取得」）と書き、**合否判定もしません**。
マウスを重ねると、どのラベルから取った値かが出ます
（用紙には説明文を入れないので、根拠はこのツールチップで確かめます）。

| 列 | 変換元ファイルのラベル |
|---|---|
| 試験力 | `最大点_試験力` / `最大点_Fm` |
| 引張強さ | `最大点_応力` / `最大点_Rm` |
| 伸び | `破断点_変位(ひずみ)` / `破断点_At` |
| 弾性率 | `弾性率_Standard` |
| 応力増加速度 | `応力増加速度` |
| ひずみ速度 | `歪速度` |
| 実績クロス変位速度 | `実績クロスヘッド変異速度` / `クロスヘッド変異速度` |
| 厚さ・幅 | 試験条件 |

見出しの耐力点も `耐力点1_応力` / `耐力点1Rp` から取ります。

用紙のグラフに重ねる注釈は **最大点 Rm** と **破断点 ×** の 2 つです。
× の位置も変換元ファイルの `破断点_変位(ひずみ)` で、横軸がひずみ [%] なので
**そのまま置きます**（応力はその位置にいちばん近い測定点の値を使い、線の上に印が乗るように
します）。このツールの破断点検出は使いません。

`合格範囲` は **変換元ファイル（`.vtav` / `.xtux`）に入っている判定範囲をそのまま読み出します。**
値は試験方法ごとに違うため、ツール側には持ちません（ハードコードしない）。
対象は次の 4 項目で、単票の判定バナーもまったく同じ範囲・同じ測定値を使います。
範囲が見つからない項目は空欄にし、**合否判定もしません**（`—`）。寸法は元から判定の対象外です。

| 表の列 | ファイル内のラベル | ファイルの単位 |
|---|---|---|
| 応力増加速度 | `応力増加速度` | MPa/s |
| ひずみ速度 | `歪速度` | /sec |
| 弾性率 | `ヤング率`（`.vtav`）／ `弾性率`（`.xtux`） | GPa → 表では N/mm² に換算 |
| 実績クロス変位速度 | `クロスヘッド変異速度` | mm/min |

#### 測定値が取れていない項目は判定しません

**合格範囲があっても、その項目の測定値が変換元ファイルに無ければ合否判定はしません**（`—`）。
装置側で設定していない項目（`.xtux` の弾性率など）を「不合格」に見せないためです。
このとき**全体の判定にも効かせません**（要確認にも不合格にもなりません）。

判定に使う測定値は、**レポートの表に出しているファイルの記録値そのもの**です。
以前はここだけこのツールの計算値（波形から求めた弾性率など）を見ていたため、
表に「取得できず」と書いてある項目が、判定バナーでは不合格になることがありました。

| ファイルの合格範囲 | ファイルの測定値 | 合否判定 |
|---|---|---|
| ある | ある | 範囲と突き合わせて `合格` / `不合格` |
| ある | **無い** | **判定しない**（`—`。全体の判定にも影響しません） |
| 無い | ある・無い どちらも | 判定しない（`—`） |

> 記録値を持たない CSV 入力だけは、このツールの計算値で判定します（それしか測定値が無いため）。
> CSV でも、計算できなかった項目は同じように判定しません。

#### 抽出のしかた

合格範囲は 20 バイトの固定レコードで格納されています。

```
+0   00 00 00 00      uint32 = 0   ┐ MARK
+4   01 00 00 00      uint32 = 1   ┘（判定有効フラグと推定）
+8   [下限] float32(LE)
+12  00 00 00 00      float32 = 0.0（区切り。判定には使わない）
+16  [上限] float32(LE)
```

MARK は汎用のバイト列なので、そのままでは 1 ファイルに数千件ヒットします。
`中間 == 0.0` / `下限 < 上限` / 有限 / 桁が妥当（`-1e5 < 下限 < 1e6`・`上限 < 1e6`）/
`(0, 0)` でない、の 5 条件を**すべて**満たすものだけを採用します。

項目との対応づけは、ラベル文字列を**生の UTF-8 部分一致**で探して起点にします
（長さプレフィックスは `.vtav` では一致しますが `.xtux` では一致しないため使いません）。
起点から前方 800 バイトの窓を MARK で走査し、最初に条件を満たしたレコードを採用します。

> **窓の打ち切り**: 窓の中に別項目のラベルが現れたら、そこで窓を閉じて次の出現位置を見ます。
> 窓を固定長のまま走査すると、項目が近接して並んでいるときに隣の項目の範囲を拾ってしまう
> ためです（合成ファイルで再現を確認）。仕様書に対するこの 1 点だけは意図的に足しています。

#### 判定を設定していない項目のゴミ範囲を弾く

`.xtux` の弾性率は、先頭出現が信号チャンネル定義で範囲が `0–0` になることがあります。
その場合は `(0,0)` フィルタで捨てて次の出現位置を探し、それでも見つからなければ空欄にします。

ただし**ちょうど `(0,0)` とは限りません**。判定を設定していない項目では、
信号チャンネル定義のバイト列がたまたま「合格範囲らしく」見えることがあり、
実測では弾性率に `1.2e-7 〜 3.4e-7 GPa` が入っていました。
`下限 < 上限` で `(0,0)` でもないので素通りし、N/mm² に換算して表示桁で丸めると
**「許容範囲 0〜0」** になって、まっとうな測定値が不合格になります。
そこで 2 つ足しています。

1. **上限の桁が、その項目としてあり得るか**（ファイルの単位のまま判定）。
   実際の規格値から十分に余裕を取った窓で、外れたものは合格範囲として採りません。

   | 項目 | 下限 | 上限 |
   |---|---|---|
   | 応力増加速度 | `1e-3` MPa/s | `1e5` MPa/s |
   | 歪速度 | `1e-8` /sec | `1e2` /sec |
   | 弾性率（ヤング率） | `1e-2` GPa | `1e4` GPa |
   | クロスヘッド変異速度 | `1e-4` mm/min | `1e5` mm/min |

2. **画面に出したとき下限と上限が同じ文字になる範囲は使いません**。
   根拠を画面で示せない以上、それで合否を出してはいけないからです（`基本設計.md` §6）。

どちらかに当たった項目は「合格範囲なし」として扱うので、**合否判定もしません**（`—`）。
> 差し替えるときは `assets/js/report.js` の `REPORT_COLS` を実データから作ります。

## 弾性率の計算区間と 0.2% 耐力線

弾性直線には **2 つの決め方**があります。既定は**装置方式**です。

| 方式 | 直線の決め方 | 位置づけ |
|---|---|---|
| **装置方式**（既定） | ファイルに記録された**弾性率の計算区間**の中の実波形点を、**すべて最小二乗回帰**した直線 | 装置が弾性率を出したときと同じ区間。**再現値** |
| 解析方式 | 応力帯の中の複数点を回帰した直線 | このツール独自の**解析値**（参考） |

> **`0.2` は「ひずみ 0.2%」のオフセット量**です。**耐力の 20% ではありません。**
> `耐力×0.2` / `耐力×0.6` は耐力応力に対する倍率で、計算区間とは別物です。
> **参考値としてだけ**持ち、計算区間・弾性直線・オフセット線の算出には使いません。

```
弾性直線     σ    = m ε + b        （計算区間内の全有効点を回帰）
オフセット線 σoff = m (ε − 0.2) + b
弾性率 E [N/mm²] = m × 100 ／ E [GPa] = m / 10
```

**0.2% 耐力点 Rp0.2** は、オフセット線と応力-ひずみ曲線の交点です。探索は
**計算区間の上限点以降から最大試験力点まで**。正から 0 以下へ変わる隣接点を**線形補間**します。
交わらないときは **「交点未検出」**とし、**差が最小の点で代用しません**。

### 計算区間をどこから取るか

| 順位 | 取得元 |
|---|---|
| 1 | `弾性率_Standard` のパラメータの**試験力**区間（例: `試験力 4667 - 14001 N`） |
| 2 | 同じパラメータの**応力**区間（例: `応力 30 - 150 N/mm2`） |
| 3 | `中間点1` / `中間点2` の**試験力**（番号は固定せず、数値の大小で下限・上限を決める） |
| 4 | 同じく**応力** |
| 5 | 復元不可 → 装置方式は使わない |

`.vtav` の結果サマリーはパラメータ欄を持たない（値アンカー方式）ため、
`弾性率_Standard` のラベル近くにある区間らしい文字列を拾って、同じ扱いにします。

区間の端は、**その値にいちばん近い実波形点**を選びます（試験開始〜最大試験力点まで。
除荷後・破断後は採りません）。端点の差率が **1.0 % を超えたら計算は続けたうえで要確認**にします。

ひずみは `変位計 ÷ 標点距離 × 100`。標点距離は `変位計1標点距離` →
解析設定のゲージ長 の順で、**設定値を使ったときは「装置値の完全再現ではない」と画面と CSV に明記**します。

### 品質区分

| `quality` | 意味 |
|---|---|
| `exact` | 計算区間を取得でき、端点差が基準以内 |
| `nearest-warning` | 端点差が 1.0 % 超 |
| `fallback-midpoint` | 区間文字列が無く、中間点から復元 |
| `manual-gauge` | 標点距離を解析設定から補完 |
| `manual-area` | 断面積・寸法を手入力 |
| `unavailable` | 計算区間または必要な波形が無い |

複数該当するときは全部を並べて出します。

### 正式値と再現値を混ぜない

| 用途 | 使う値 |
|---|---|
| レポートの数値欄・見出し | **ファイルの正式値** |
| グラフ上の三角マーカー | 再現交点 |
| 解析タブ | 正式値・再現値・差を併記 |
| CSV | 正式値・再現値・差を**別項目**で出力 |

**再現値でファイル正式値を上書きしません。** 計算区間を復元できないときは、
解析方式の直線を正式線としてレポートに出しません（耐力線なし）。

### 単票の操作

線図ツールバーの **`重ねる注釈`** から、耐力線の方式と重ねる要素を選びます。

- **耐力線をどちらで引くか** — 装置方式（ファイル計算区間）／解析方式（複数点回帰）
- **耐力線まわりに重ねるもの** — 弾性直線／0.2% オフセット線／計算区間端点（下限・上限）／耐力点 Rp0.2／解析線を比較表示

装置方式を復元できないファイルでは選択肢を無効にし、**理由を出したうえで解析方式へ落とし**、
「装置方式を復元できないため解析方式を表示」と明示します。

色は **計算区間端点と弾性直線＝青**（上限以降は破線）、**0.2% オフセット線＝橙破線**、
**Rp0.2＝橙の上向き三角**、**解析回帰線＝灰色細線（参考）**。
凡例には計算区間・実波形点番号・回帰点数・R²・弾性率・オフセット線式・正式値との差を出します。

根拠は `根拠` ボタンで開きます（既定はたたみ。警告があるときはボタンが警告色になります）。

```
計算区間 30.0〜150.0 N/mm²   取得元 弾性率_Standard の計算区間
実波形 第 95〜484 点（390 点を回帰）   R² 0.99986
弾性率 72,494 N/mm²（ファイル値との差 -0.45 %）   標点距離 50.0 mm
```

## 単票の画面の作り

線図が主役なので、**線図に面積を渡す**ことを軸に組み立てています（`基本設計.md` §1）。

| 段 | 中身 | 既定 |
|---|---|---|
| 見出し | ファイル名・形式・サイズ・検出件数・CRC・表示切替 | 常に見える |
| タブ | レポート項目／線図／**解析 `n`**／結果全項目／波形／変更履歴 | 常に見える |
| ツールバー 1 | 線図の切替・X 軸・Y 軸・`重ねる注釈 n/m`・時間-応力を並べる | 常に見える |
| ツールバー 2 | `拡大して確認`・`根拠`・`表示範囲を数値で指定` | 常に見える |

### 合否は 1 か所だけに置く

**単票に判定バナーは置きません。** 合否は**左のファイル一覧**（`変換済・合格` /
`変換済・不合格` …）で分かります。同じ情報を 1 画面に 2 つ出すと、線図の面積を食ううえに
どちらを見ればよいか迷います。

### たたむものと、たたまないもの

既定でたたむのは **「読まなくても作業できる説明」**だけです。

| もの | 既定 | 理由 |
|---|---|---|
| 全体図（ミニマップ） | たたむ | 拡大したときだけ要る |
| 凡例 | たたむ | マーカーには線図上に文字が出るので、色の対応は後から見れば足りる |
| 耐力線の根拠 | たたむ | 数値の裏取りをするときだけ要る |
| 表示範囲の数値入力 | たたむ | ドラッグとホイールで足りることが多い |
| **要確認・警告** | **たたまない** | 注意が要る事実は隠さない |

**警告があるときは `根拠` ボタン自体が警告色になり、`要確認 n` と件数が出ます。**
たたんでいても「見るべきものがある」ことは必ず分かります（§3・§4）。
たたんだトグルには中身の要約（`根拠（30.0〜150.0 N/mm²）` `凡例 9 項目`）を出して、
開く価値があるかを開く前に判断できるようにしています（§2）。

補助表示を全部開いても**ページ自体はスクロールしません**。線図には下限の高さがあり、
あふれるぶんは足元の領域が内側でスクロールして吸収します。

## 不合格のとき、次にすることが分かる

「不合格」の 3 文字だけでは、**なぜ・どこを見れば・何が悪いのか**が分かりません。
**単票 › 解析**の内訳で、引っかかった項目 1 件ずつに次を付けています。
**タブの数字が確認したい項目の件数**で、不合格なら赤、要確認なら橙の丸が付きます。

| 見えるもの | 中身 |
|---|---|
| なぜ | **根拠**（測定値・単位・許容範囲・出どころのラベル） |
| 何が悪いのか | **原因の区分**（下表） |
| どこを見ればよいか | その場から飛べるボタン。**線図は根拠の位置まで拡大**して開きます |
| 次にすること | 区分ごとの直し先を 1 行で |

### 原因の区分（直し先が違う 3 つ）

| 区分 | 意味 | 直し先 |
|---|---|---|
| **試験** | 装置が記録した測定値が、同じファイルに入っている判定範囲の外 | 試験そのものの結果です。試験速度の設定・試験片の寸法を確認します |
| **データ** | 変換元ファイルに必要な値が無い／解析できない | 変換元ファイル側の問題です。波形・解析タブで欠けているものを確認します |
| **設定** | このツールの設定値が実態と合っていない | `設定 › …` で直せます。内訳から直接開けます |

**データ異常か・試験異常か・設定ミスか**をここで切り分けられます。

- 状態は**アイコン ＋ 文字 ＋ 色**の三重表現です（§3）。区分も色だけでなく文字で出します。
- 飛べないタブ（CSV 入力の波形など）のボタンは **disabled にしたうえで理由を画面に出します**（§4）。

レポート画面の `判定: 不合格` チップも押せます。押すと単票 › 解析の内訳へ移ります。

## 伸び（`破断点_変位(ひずみ)`）の抜き出し

**「伸び」の真値は、変換元ファイルに記録された結果サマリー値 `破断点_変位(ひずみ)` です。**
波形からの計算値（式①→②法／島津法）は参考扱いで、ファイル記録値がある限りそちらを優先します
（計算値は破断記録の有無や丸めで数 pt ずれます）。**同じラベル名でも `.vtav` と `.xtux` で
格納構造がまったく違う**ので、フォーマットを判定してから方式を使い分けます。

フォーマット判定は先頭 64 バイト内の `TXVFileVersion`（あれば `.vtav`）、
無ければ拡張子（`.vtav` → vtav ／ それ以外 → xtux）です。

### `.vtav` — UTF-8・バイトアンカー方式

文字列は `[1バイト長][UTF-8値]`、値はラベル近傍にアンカーとして散在します。

1. **起点ラベル**: UTF-8 の `破断点_変位(ひずみ)`（長さ `0x1B` = 27 バイト）を検索します。
2. **結果領域に限定**（誤検出防止の要）: `[最初の日時オフセット, 「試験条件」オフセット)` の
   範囲だけを見ます。テンプレート側にも同名ラベル（値 `0`）があるため、これを外さないと
   そちらを拾ってしまいます。
3. **値アンカー走査**: ラベルの後 200 バイト以内で最初に現れる
   `[長さ 01–0F][ -?\d[\d.\-]{0,14} ] 00 [01|02] 00 00 00` を値とします。
4. **除外**: 値 `0`（テンプレートの初期値）。パラメータの `70`（＝ MAX の % レベル）は
   アンカー末尾形ではないので自然に外れます。

→ 結果: `破断点_変位(ひずみ), %, 8.4`

> 単位の `%` は、`.vtav` の文字列ウォーカーが英数字も漢字も含まない単独記号を落とすため
> トークンに出てきません（近傍から拾うと隣の `mm` などを拾ってしまいます）。
> この項目の単位はラベルから確定するので `%` を補います。

### `.xtux` — UTF-16LE・順序構造方式

文字列は `[0x3E][長さ(偶数)][UTF-16LE値]`。バイトアンカー走査は使えません。
ヘッダの後ろに「ラベル列 → 数値列」が同じ順で並ぶので、順序で対応づけます。

1. **ブロック起点**: `名前` を見つけ、`単位` まで読み飛ばします。
2. **ラベル行収集**: `単位` の直後から、数値が始まる直前まで。各行は単位語
   （`%` `N` `N/mm2` …）で区切ります。
3. **数値列収集**: ラベル行の直後から連続する数値を順に取得します。
4. **対応づけ**: i 番目のラベル ← i 番目の数値。

→ 結果: `破断点_変位(ひずみ), %, 23.61317`（パラメータは「MAXの%レベル 70」）

> **パラメータの中の数値**: 数値を見たら即「値の列の始まり」と見なすと、
> `破断点_変位(ひずみ)` のパラメータ `70` でラベル行の収集が止まり、この行そのものが落ちて
> 以降の値も 1 つずつずれます。行の切れ目（＝直前の行が単位語で閉じている）に立っている
> 数値だけを値の列の始まりとし、**行の途中に出る数値はその行のパラメータとして取り込みます**。

### どこに効くか

抜き出した値は結果サマリーへ反映してから使うので、**レポートの表・グラフの `×`・
単票 › 解析の「伸び」カードは、すべて同じ値**になります。
ファイルに値が無いときだけ、下の検出結果（計算値）へ落とします。

## 破断点の決定（**試験段階**）

**このツールの破断点検出はまだ試験段階です。伸びの値には使いません**
（レポートも解析カードも、変換元ファイルの `破断点_変位(ひずみ)` をそのまま出します）。

**単票 › 解析 › 破断点の決定**に、式①→②法・島津法・波形の末端・元ファイルの値を
並べているので、検出結果と装置の答えを見比べるのに使ってください。

| 行 | 意味 |
|---|---|
| 式①→②法 | 急落開始（式①）を探し、そこから試験力が Fmax の `fracture_k2` 未満に下がった点 |
| 島津法 | 1 秒間に Fmax の `shimadzuPctOfMaxForce` 以上低下した最初の点 |
| 波形の末端 | 記録の最後の点と、ひずみの最大値 |
| 元ファイルの値 | 装置が出した破断点のひずみ（**伸びはこれを使います**） |

破断後も装置は記録を続けるため、**波形の末端のひずみは破断点より大きくなります**。
どこを破断点と見るかで計算値は変わるので、しきい値は 設定 › 破断・伸び で調整できます。

## 「変換できませんでした」と出たとき

本文が **`ファイルの中身ではなく、ファイルそのものに手が届きませんでした`** で始まるときは、
解析より手前、**ファイルを読む段階**で止まっています（ブラウザの `NotReadableError`）。
中身の問題ではないので、ファイルの形式やこのツールの設定は関係ありません。

| 心当たり | 直し方 |
|---|---|
| そのファイルを **TrapeziumX などで開いたまま** | 開いているアプリを閉じてから「もう一度読む」 |
| **OneDrive / SharePoint / ネットワークドライブ / USB** 上のファイル | エクスプローラーで右クリック →「このデバイス上で常に保持する」でローカルに落としてから入れ直す（「オンラインのみ」の実体が無いファイルは読めません） |
| 選んだあとに **移動・更新・削除された**（試験機が書き込み中など） | 「ファイルを選び直す」で入れ直す |

エラー表示の下に **`もう一度読む`** と **`ファイルを選び直す`** を出しています。
一時的なロックやクラウドの取り寄せ待ちなら、`もう一度読む` で通ります
（内部でも、間を置いて別経路でもう一度読み直しています）。
`サイズ 0 B` と出ているときは中身が空です。エクスプローラーでサイズを確かめてください。

## 波形の切り出し（破断後まで採る）

波形は 7 バイトの区切りマーカーで 1 レコードずつ並んでいます。

```
01 00 00 00 [00|01] 01 01
            ~~~~~~~ 破断前 = 0x00 ／ 破断後 = 0x01
```

**5 バイト目は破断の前後で変わるフラグ**です。チャネルの相対オフセット
（`Time` −8 ／ `Stroke` −4 ／ `Force` +29 ／ `Extensometer` +37）も
レコード周期（stride）も前後で変わりません。

ここを `0x00` 固定で探すと、**応力がゼロへ落ちていく破断後のレコードが丸ごと落ち**、
線図が破断点でぷっつり切れます（元 Trapezium は破断後まで描いています）。
そこで `0x00` / `0x01` のどちらも受理して走査します。緩めたことで増える偽マーカーは、
これまでどおり**最頻のレコード周期に一致する点だけを採る**フィルタが弾きます。

実測での効き方（`.vtav`）:

| ファイル | 点数 | 伸び計 最大 | 最終試験力 |
|---|---|---|---|
| `20260701_0014_N4412S0_UL` | 3449 → **3469** | 8.40 % → **11.61 %** | 71.4 % → **0.7 %** of Fmax |
| `20260721_2240_L3061E0_0-3UL` | 3165 → **3185** | — | 99.6 % → **1.0 %** of Fmax |

`.xtux`（`20260701_0931_H5081J1_L`）は 1580 → 1581 点・stride 58 のままで、副作用はありません。

## 線図が途中で止まって見えるとき

**データは欠けていません。** 波形は全点そろっていて、CSV にもそのまま出ます。
止まって見えるのは、線図の X 軸に選んだ**チャネル自体が途中で動かなくなっている**ためです。

破断で伸び計を外す（止める）装置では、`Extensometer_mm` が破断点で止まり、
`Stroke_mm` だけが試験の最後まで伸びます。伸び計基準のひずみ ε もそこで止まるので、
`ひずみ-応力` や `応力-伸び` の線図は破断点で終わります。

| 確認する場所 | 見るもの |
|---|---|
| 単票 › 波形 › **チャネルの終端** | 各チャネルの最終値・最小〜最大・**最後に動いた点**。止まっているチャネルには警告が付きます |
| 単票 › 線図 › X 軸 | `ストローク` または `ひずみ（ストローク基準）` を選ぶと最後まで描けます |
| 単票 › 線図 | レポートの用紙には説明を入れないので、止まっている理由はこちらで確認します |

`ひずみ（ストローク基準）` は `ストローク ÷ ゲージ長 × 100` です。機械のたわみを含むため、
規格上のひずみ（伸び計基準）とは別物の参考値として扱ってください。

3 通りの合成ファイル（破断後に伸び計が **伸び続ける / 止まる / 揺れる**）で切り分けた結果、
波形の復元（`extractWaveform`）・解析・作図のいずれにも打ち切りは無く、
**止まって見えるのは伸び計チャネルが止まる場合だけ**であることを確認しています。

- フォーマット自動判別（先頭 64 バイトのマジック優先 → 拡張子）。拡張子偽装でも正しく処理します。
- TLV 文字列トークン抽出：`.xtux` は UTF-16LE（`0x3E`＋長さ）、`.vtav` は UTF-8（1 バイト長）。
- 結果サマリー抽出：`.vtav` はバイトアンカーで値を確定、`.xtux` は「名前→単位→値」の順序構造。
- `.xtux` の寸法は UTF-8 側の寸法セクションから補完します。
- 生波形はマーカーの等間隔出現からレコード周期を推定して float32(LE) で復元します。

**解析**（仕様書 §11〜§17）

- ひずみ-応力線図（SS 曲線）／時間-応力線図。耐力点▽・破断点×・0.2% 耐力★・回帰直線・
  0.2% オフセット線・直線域バンドを重ねて表示します。
- 算出値：引張強さ Rm、耐力（速度法）、0.2% 耐力、伸び（式①→②法／島津法）、
  応力増加速度、ヤング率、ひずみ速度①②、直線性 R²。
- 応力の取得は入力経路で切り替わります。CSV 入力は応力列をそのまま使用し、
  DAT 入力は全点 SS 曲線を `σ = 試験力 ÷ 断面積 A` で復元します（断面積は試験条件から自動、
  無ければ画面で入力）。
- 解析パラメータ（ゲージ長・速度閾値・直線域バンド・破断判定係数 等）は設定ダイアログで
  変更でき、変更するとその場で全ファイルを再解析します。JSON で書き出し／読み込みもできます。

**算出できないときは、できないと書きます。** 時刻列が無ければ時間依存量（速度法耐力・
応力増加速度・ひずみ速度）を「算出不可」と明示し、理由を画面に出したうえで、
Rm・伸びなど算出できる量は継続して計算します。

## 画面の考え方（`基本設計.md` に対応）

- **面積は頻度 × 重要度**：最初はドロップ領域が画面の主役。変換後は結果と線図に面積を渡し、
  設定・パラメータはダイアログとメニューへ退避します。
- **次にすることは常に 1 つ**：主要動作は右上の 1 ボタンだけ。位置は固定でラベルだけが変わります。
  件数・ファイル数・合計サイズはこちらで数えて文言に入れます。
- **状態は色だけで伝えない**：合格／要確認／不合格・成功／失敗は必ずアイコン＋文字＋色の三重表現。
- **できないことは書く**：使えないタブ・押せない拡大ボタンは disabled にしたうえで、
  その理由を画面に出します。
- **危ない操作は主要動線に置かない**：全削除は「⋯」メニュー。実行後は確認ダイアログではなく
  「取り消し」を出します。
- **出どころ・単位・根拠を出す**：判定の元になったラベル、形式判定の根拠、入力の CRC-32、
  文字コード、断面積の求め方、各特性値の算出式と使用点数・R² を画面に併記します。
- **見た目の値はトークンから**：色・余白・角丸・文字サイズ・高さ・アニメーション時間は
  すべて `assets/css/tokens.css` に集約しています。メインカラーは深い青（`--blue-900`）、
  アクセントは同系のティール、ベースは青みを含んだニュートラルです。ダークテーマにも追従します。
- **スクロールレス**：ページ自体はスクロールせず `100dvh` に収め、件数が増える一覧や表は
  その領域の内側だけをスクロールさせます。レポートの用紙も画面の高さに合わせ、余った高さは
  最下部のグラフに渡します。レポートの用紙は A4 の実寸で置き、既定では画面に入る倍率まで
  縮めて 1 枚全部を見せます。
- **数えさせない・確認させない**：ドロップしたデータは変換する以外に使い道が無いので、
  変換の可否は聞かずにそのまま線図まで進みます。

## 検証

`1.py` と同じ入力に対して、`report` / `results` / `conditions` / `waveform` の 4 種の CSV が
**バイト単位で一致**することを確認しています（波形の丸めは Python の `round()` と同じ偶数丸め）。
ただし**波形の点数は一致しません**。`1.py` は破断後のレコードを取りこぼしており、
このツールは「波形の切り出し」のとおり破断後まで採るため、その分だけ多く出ます。
拡張子偽装・波形なし・寸法なし・時刻列なしの各ケースも、理由を表示したうえで処理を継続します。
20 MB / 15 万点の波形でも変換＋解析が約 1.2 秒、線図は画素列ごとの間引きで即座に描画します。
